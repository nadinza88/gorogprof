# ARCHITECTURE.md — «Навигатор будущего»

Целевая аудитория: дети 7–14 лет; взрослые (родители и педагоги) могут читать результат и переходить к информации о клубе.

## Принципы
- Начать с простого статического веб-сайта; MVP не нуждается в сервере.
- Подсчёт интересов — обычный тестируемый код, а не генерация AI.
- Минимум зависимостей, никаких секретов или личных данных в клиенте.
- Тексты и правила подсчёта отделены от UI.
- Осмотреть репозиторий до создания файлов и ничего не перезаписывать без проверки.

## Целевая среда и стек
Рекомендуемый вариант: React + TypeScript + Vite для интерфейса с повторно используемыми компонентами; CSS с адаптивной вёрсткой. Если после осмотра Codex решит, что vanilla HTML/CSS/JS проще и надёжнее для текущего MVP, он должен обосновать выбор перед изменением решения. Пакетный менеджер и команды определить по фактическому окружению.

Платформа: браузер, компьютер/планшет/телефон.
Публикация: Cloudflare Pages, связанный с GitHub.

## Границы системы
- Клиентский сайт отображает квест и считает профиль.
- GitHub хранит исходный код.
- Cloudflare Pages публикует статическую сборку.
- В MVP нет backend, БД, авторизации и сторонних API.
- Результат печатается/сохраняется пользователем в PDF средствами браузера (window.print + отдельные print CSS); не нужен серверный генератор PDF.

## Предлагаемые модули
- `src/data/questions.ts`: вопросы, варианты ответов, категории и веса.
- `src/lib/scoring.ts`: детерминированный расчёт результата.
- `src/components/`: кнопки, карточки ответов, индикатор прогресса, диалог/персонажи.
- Экраны: старт, вопрос, результат, профессии/идеи.
- `src/assets/`: изображения с подтверждёнными правами использования.
- `src/styles/`: дизайн-токены, адаптивные стили и состояния.
- `README.md`: реальные инструкции запуска, тестирования и публикации.
- `PRODUCT.md`, `ARCHITECTURE.md`, `ACCEPTANCE.md`, `AGENTS.md`, `START_CODEX.md`: спецификации.
- `PROJECT_STATUS.md`: этап, доказательства тестирования, ограничения и следующий шаг.

Подтвердить структуру после осмотра; не создавать лишние абстракции заранее.

## Модель данных
- Question: id, prompt, text/dialogue, scene key, options.
- Option: id, text, categoryId — ровно одно из пяти направлений интересов для базового подсчёта; optional feedback текст для реакции персонажа.
- InterestCategory: id, label, description.
- ProjectSuggestion: title, description, related categories.
- QuizState: currentQuestionIndex, answersByQuestionId.
- InterestResult: totals, display scores (если нужны), leading categories, suggestions.

## Логика квеста
- Хранить ответы по id вопроса.
- Кнопка «Назад» меняет индекс и не начисляет очки.
- «Отменить выбор» удаляет только ответ текущего вопроса.
- Изменённый ответ заменяет предыдущий; баллы не суммируются повторно.
- Итог рассчитывается из выбранных ответов, а не из побочных эффектов кликов.
- При равных результатах показывать несколько ведущих интересов.
- Итог недоступен до заполнения всех обязательных вопросов.

## Иллюстрации и лицензии
Референс предоставлен пользователем и служит направляющей стиля. Использовать только собственные или лицензированные изображения. Не брать случайные картинки без проверки прав.
Персонажи: Фокс — дружелюбный рыжий лисёнок с рюкзаком; робот — маленький округлый робот с белым корпусом и голубым свечением глаз. Сохранять единый дизайн между сценами. Текст на иллюстрациях не использовать вместо HTML-текста.

## Приватность

- Не устанавливать трекеры/рекламные SDK без отдельного решения владельца.
- Не хранить секреты во frontend.
- Ссылку на клуб хранить в понятной конфигурации и проверить перед релизом.
