# START_CODEX.md — запуск разработки

Прочитай полностью `PRODUCT.md`, `ARCHITECTURE.md`, `ACCEPTANCE.md`, `AGENTS.md` и все существующие файлы проекта.

## Первый ответ — только анализ, не редактируй код
1. Перескажи цель, MVP и исключённые возможности.
2. Осмотри репозиторий, файлы, окружение, runtime и доступные команды.
3. Перечисли открытые вопросы, допущения и основные риски.
4. Предложи минимальный вертикальный срез, который можно запустить в браузере.
5. Перечисли изменения файлов, команды build/test, критерии приёмки и ожидаемые артефакты.
6. Не меняй файлы до одобрения этого плана пользователем.

## После одобрения
- Работай небольшими проверяемыми вехами; не обещай время завершения.
- Реализуй сначала работающий вертикальный срез, затем остальные вопросы и визуальную полировку.
- После каждой существенной вехи обновляй `PROJECT_STATUS.md`: выполнено, реальные тесты, непроверенное, блокеры, следующая задача, текущий commit.
- Фактически запускай доступные тесты и сборку, записывай их результаты.
- Сохраняй восстановимые GitHub milestones/коммиты, если доступ на запись имеется и работа одобрена.
- Остановись и спроси при смене требований, платных сервисах, секретах, сборе чувствительных данных, разрушительных изменениях или production-релизе.
- В финале сообщи текущий результат, команды preview, доказательства тестов, ограничения и следующую задачу.

## После разработки
Не считать окончание кодирования окончанием проекта. Проверь preview, пройди ACCEPTANCE.md, зафиксируй приёмку и публикуй production только после отдельного явного подтверждения владельца.
